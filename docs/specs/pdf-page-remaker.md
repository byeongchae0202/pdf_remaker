# PDF 페이지 추출 및 병합 웹앱

## Status

In Progress

## Problem

여러 PDF에서 필요한 페이지만 골라 원하는 순서로 재구성한 하나의 PDF를 만드는 작업을 간편하게 제공한다.

## User Scenarios

- 개인 사용자가 여러 PDF를 업로드한다.
- 사용자가 업로드된 PDF의 페이지를 확인한다.
- 사용자가 썸네일 클릭 또는 페이지 번호 입력으로 필요한 페이지를 선택한다.
- 사용자가 선택한 페이지의 순서를 확인하고 드래그 앤 드롭으로 변경한다.
- 사용자가 필요하면 페이지별 회전 방향을 지정한다.
- 사용자가 선택한 페이지를 하나의 PDF로 생성한다.
- 사용자가 생성된 PDF를 미리보고 다운로드한다.

## Scope

### In Scope

- 웹 애플리케이션 형태의 PDF 처리
- 개인 사용자의 비로그인 이용
- 여러 PDF 업로드
- PDF 페이지 선택
- 선택 페이지 순서 변경
- 페이지 회전
- 선택한 페이지의 PDF 생성 및 병합
- 생성된 PDF 미리보기
- 생성된 PDF 다운로드
- 암호화 PDF의 파일별 비밀번호 입력
- 웹앱 화면 언어 선택
- 처리 후 업로드 파일과 결과물 즉시 삭제
- 데스크톱 우선 및 모바일 대응

### Out of Scope

- 사용자 계정 및 로그인
- 사용자별 작업 기록 보존
- 브라우저 종료 또는 새로고침 이후 작업 복구
- 개발 환경과 운영 환경의 분리

## Functional Requirements

### File Upload and Inspection

- 사용자는 여러 PDF를 한 번의 작업에 업로드할 수 있어야 한다.
- 업로드 후 각 PDF의 페이지를 확인할 수 있어야 한다.
- 업로드 파일의 크기와 개수 제한은 안정성과 비용을 고려해 기술적으로 정한다.
- 암호화된 PDF는 파일별 비밀번호를 입력받아 처리할 수 있어야 한다.
- 비밀번호가 없거나 올바르지 않은 경우 해당 파일의 처리 상태를 사용자에게 알려야 한다.

### Page Selection and Ordering

- 사용자는 페이지 썸네일을 클릭해 페이지를 선택할 수 있어야 한다.
- 사용자는 페이지 번호 입력으로 페이지를 선택할 수 있어야 한다.
- 사용자는 선택한 페이지의 순서를 드래그 앤 드롭으로 변경할 수 있어야 한다.
- 사용자는 선택한 페이지를 원본 파일 및 페이지 순서와 무관하게 원하는 순서로 구성할 수 있어야 한다.
- 원본 페이지의 시각적 내용은 가능한 한 그대로 유지해야 한다.
- 사용자는 페이지별 회전을 지정할 수 있어야 한다.

### PDF Generation and Preview

- 사용자는 선택과 순서 변경 결과를 생성 전에 확인할 수 있어야 한다.
- 시스템은 선택된 페이지를 사용자가 지정한 순서의 하나의 PDF로 생성해야 한다.
- 생성된 PDF의 페이지 내용과 시각적 형식은 원본을 그대로 유지해야 한다.
- 사용자는 생성된 PDF를 미리볼 수 있어야 한다.
- 사용자는 생성된 PDF를 다운로드할 수 있어야 한다.

### Language

- 사용자는 웹앱 화면 언어를 선택할 수 있어야 한다.
- 한국어, 영어, 일본어, 중국어를 포함한 전 세계 주요 언어를 지원해야 한다.
- 지원 언어의 정확한 목록과 초기 기본 언어는 별도 결정이 필요하다.

### Error Handling

- 여러 파일 중 일부에 문제가 있으면 사용자가 문제 파일을 제외할지 결정할 수 있어야 한다.
- 사용자가 문제 파일을 제외하면 정상 파일을 사용해 작업을 계속할 수 있어야 한다.
- 사용자가 문제 파일을 제외하지 않으면 해당 작업은 계속 진행하지 않아야 한다.
- 파일 업로드, PDF 분석, PDF 생성 단계의 오류를 구분해 안내해야 한다.

### Data Handling

- 로그인 없이 사용할 수 있어야 한다.
- 업로드 파일과 생성 결과물은 처리 후 즉시 삭제해야 한다.
- 업로드 문서에는 개인정보 또는 민감한 정보가 포함될 수 있다.
- 브라우저 종료 또는 새로고침 시 진행 중인 작업이 사라져도 된다.

## Non-Functional Requirements

### Platform

- 웹 애플리케이션으로 제공한다.
- 데스크톱 사용을 우선하되 모바일 화면에서도 사용할 수 있어야 한다.

### Azure

- Azure를 사용해야 한다.
- Azure 리소스는 하나의 리소스 그룹에서 관리한다.
- 개발 환경과 운영 환경을 분리하지 않는다.
- 비용 최소화를 우선한다.
- 업로드 파일은 영구 저장하지 않고 임시 저장 후 삭제한다.

### Proposed Technical Direction

아래 항목은 제품 요구사항이 아니라 구현을 위한 기술 선택이다.

- 프론트엔드: React 기반 단일 웹 애플리케이션
- 웹 호스팅: Azure Static Web Apps의 비용 효율적인 구성
- 서버 처리: Azure Functions의 소비 기반 실행 모델
- 임시 파일 저장: Azure Blob Storage의 임시 컨테이너와 수명 주기 삭제 정책
- 비밀 및 설정: Azure Managed Identity와 애플리케이션 설정
- 모니터링: Azure Application Insights의 최소 구성
- Azure 리전: 필요한 Azure AI 서비스의 가용성과 비용을 확인한 뒤 선택

## Acceptance Criteria

- [ ] 로그인 없이 웹앱에 접근할 수 있다.
- [ ] 여러 PDF를 업로드하고 각 페이지를 확인할 수 있다.
- [ ] 썸네일 클릭으로 페이지를 선택할 수 있다.
- [ ] 페이지 번호 입력으로 페이지를 선택할 수 있다.
- [ ] 선택 페이지의 순서를 드래그 앤 드롭으로 변경할 수 있다.
- [ ] 페이지별 회전 결과가 생성 PDF에 반영된다.
- [x] 암호화 PDF에 파일별 비밀번호를 입력해 처리할 수 있다.
- [ ] 문제 파일을 제외할지 사용자가 선택할 수 있다.
- [ ] 선택한 페이지만 지정된 순서로 하나의 PDF로 생성된다.
- [ ] 생성 PDF에서 원본 페이지의 시각적 내용이 유지된다.
- [ ] 생성된 PDF를 미리보고 다운로드할 수 있다.
- [x] 업로드 파일과 결과물을 서버에 영구 저장하지 않고 요청 및 브라우저 메모리에서만 처리한다.
- [ ] 데스크톱과 모바일 화면에서 핵심 작업을 수행할 수 있다.

## Implementation Notes

현재 구현된 범위:

- React + Vite 기반 웹앱 초기 구조
- 브라우저에서 PDF 여러 개 업로드 및 페이지 수집
- PDF.js 기반 페이지 썸네일 표시
- 썸네일 클릭 및 페이지 번호 입력을 통한 선택
- 선택 페이지의 이동 버튼 및 드래그 앤 드롭 순서 변경
- 선택 페이지별 90도 회전
- pdf-lib 기반 PDF 생성
- 생성 PDF 미리보기 및 다운로드
- Azure Static Web Apps 설정 파일과 비용 최소화 방향의 개발 문서

아직 구현하지 않은 범위:

- 서버에서의 암호화 PDF 복호화 및 원본 벡터 구조 보존
- 웹앱 전체 문구의 다국어 번역
- Azure Blob Storage를 사용하는 배포 구성과 수명 주기 삭제 정책
- 실제 Azure 리소스 생성 및 배포

배포 템플릿은 추가했지만 Azure 인증이 없는 환경에서는 실제 리소스 생성 및 배포를 수행하지 않았다.

암호화 PDF는 브라우저에서 파일별 비밀번호를 입력받아 PDF.js로 해독한 뒤 페이지를 이미지로 렌더링해 결과 PDF에 삽입한다. 따라서 암호화 파일의 결과 페이지는 시각적으로 유지되지만 텍스트 선택 및 벡터 편집성은 보장하지 않는다.
